CookSafe – LPG Guard

Be Safe. Cook Safe.

A connected LPG safety prototype that monitors for gas leaks and flame hazards, raises local alerts, and can command a servo-based regulator shut-off. An Android companion is being developed for remote monitoring and valve control through Firebase Realtime Database.

Category: IoT · Embedded Systems · Android · Hardware + Software
Team: RoboNova  ·  My role: Team Leader, Embedded Systems & Software Developer

ESP32MQ-6Flame sensorFirebaseKotlinJetpack Compose

From sensor to screen

Telemetry and commands connect the device and app. Essential detection, local alerting, and shut-off logic is designed to work without an internet connection.

02 / Hardware engineering

The physical system

Component roles in the current prototype design. Calibration, integration, mechanical fit, and power behavior remain active engineering work.

01 · CONTROL

ESP32 DevKit

Main microcontroller for sensor sampling, local decisions, and Wi-Fi connectivity.

02 · GAS SENSING

MQ-6 gas sensor

Provides a signal used to detect possible LPG presence; readings require calibration and validation.

03 · FLAME SENSING

Flame sensor

Provides a flame-hazard input to the device's hazard-evaluation logic.

04 · ACTUATION

Servo motor

Drives a mechanical regulator shut-off mechanism; actuation depends on alignment and adequate power.

05 · LOCAL ALERT

Buzzer + status LEDs

Buzzer for audible alerts; red/green LEDs for hazard/safe indication and blue LED for Wi-Fi status.

06 · INPUT

Physical buttons

Manual emergency shut-off, Wi-Fi setup, and reset controls for device operation.

07 · POWER

Power subsystem

Rechargeable battery arrangement and voltage regulation for stable operation of the controller and servo.

08 · DISPLAY

OLED display Optional · if fitted

Local readings or status display only if an OLED is present in the showcased hardware build.

09 · INTEGRATION

Assembly & PCB

Sensor wiring, soldering, and board-level implementation as the prototype evolves.

05 / Engineering work

Problems we’re working through

These are ongoing engineering considerations, not claims of solved or production-validated behavior.

Sensor calibration and reducing false positives across operating conditions.
Servo current demand, voltage stability, and safe power delivery during actuation.
Battery management and regulated power for the complete device.
Reliable device pairing and cloud communication.
Keeping local hazard logic available during Wi-Fi or cloud outages.
Mechanical alignment and repeatable regulator actuation.
